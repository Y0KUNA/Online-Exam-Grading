# Hệ thống số hóa và quản lý chấm bài thi tự luận trực tuyến — 03. Components
> Phiên bản: 2.0 (hợp nhất v1.0 + v1.1) | Ngày hợp nhất: 2026-09-22 | Trạng thái: final
> Ghi chú hợp nhất: tài liệu này thay thế cả 03-components-ver1.0.md và 03-components-ver1_1.md. Web Client, API Gateway, Submission Service và Object Storage cập nhật theo luồng upload presigned POST direct-to-MinIO (ADR-013). Các mục khác giữ nguyên nội dung v1.0.

## Web Client
Trách nhiệm: giao diện EXAM_OFFICE/GRADER/COUNCIL; upload; theo dõi SSE; viewer PDF + rubric side-by-side; form điểm/review/export. Input là thao tác người dùng/JWT; output là REST, EventSource/SSE, và request upload multipart-form trực tiếp tới route pass-through `/storage/*` trên Gateway. Chỉ gọi API Gateway, không gọi service/Object Storage trực tiếp — kể cả upload cũng đi qua Gateway (route proxy, không phải qua Submission Service) chứ không có domain MinIO riêng nào lộ ra client ngoài `fields`/`url` do backend cấp. Dự kiến React + TypeScript + PDF.js. Đáp ứng FR-009, FR-013.

## API Gateway
Trách nhiệm: entry point duy nhất, TLS boundary, kiểm chữ ký/hạn JWT, route, request-size/rate-limit và tạo internal identity headers có HMAC. Bổ sung: route pass-through `/storage/*` chuyển tiếp nguyên trạng (method, headers, query string, body streaming, `proxy_request_buffering off`) tới MinIO nội bộ — route này không parse/validate nghiệp vụ, chỉ forward theo path, và không mở port/domain mới ra ngoài. Input: HTTP/SSE + Bearer JWT (route API), hoặc HTTP PUT/POST theo presigned policy (route storage); output: request nội bộ tới đúng service hoặc MinIO, giữ streaming cho SSE và cho upload lớn. Phụ thuộc cấu hình public key/JWKS của cơ chế xác thực bên ngoài đặc tả. Dự kiến Spring Cloud Gateway hoặc Nginx+auth middleware; chọn Spring Cloud Gateway để đồng nhất Java stack. Không thực hiện resource authorization thay service, và không thực hiện resource authorization cho route storage (việc này đã xảy ra trước đó khi Submission Service cấp presigned policy) (FR-023).

## Identity/Pseudonym Service
Trách nhiệm: roster, import CSV/XLSX, candidate master, sinh phách CSPRNG, unique phách theo exam, mapping candidate↔submission↔pseudonym, lịch sử phách, resolve danh tính cho EXAM_OFFICE và purge phách/mapping khi retention hết. Input: REST từ Gateway và internal REST từ Submission/Result; output: candidate/pseudonym metadata đã lọc theo role. Phụ thuộc Identity PostgreSQL; không phụ thuộc DB khác. Dự kiến Java 21 + Spring Boot + PostgreSQL + Apache POI cho XLSX. Ranh giới cứng: chỉ service này lưu mapping danh tính/phách (FR-005, FR-008, FR-019, FR-025, BR-006).

## Submission Service
Trách nhiệm: tiếp nhận metadata upload (không còn nhận bytes PDF trực tiếp); sinh presigned POST policy cho MinIO và xác minh object sau khi client tự upload (HEAD, kiểm size); metadata/file references; state machine; validation; worker anonymization; template vùng phách; trạng thái SSE/snapshot; quyền cấp URL ORIGINAL/ANONYMIZED; retention purge file/metadata; job định kỳ dọn upload dang dở/orphan object. Input: REST (JSON, không multipart cho init/complete), RabbitMQ jobs; output: trạng thái, presigned POST policy, SSE và presigned URL đúng quyền. Phụ thuộc Submission PostgreSQL, RabbitMQ, MinIO/S3, Identity REST; phối hợp Exam/Result REST. Dự kiến Java 21 + Spring Boot, Apache PDFBox, Spring AMQP, AWS S3 SDK/MinIO SDK (dùng cho việc sinh presigned policy và HEAD object, không còn dùng để nhận multipart file trực tiếp từ client). Worker nằm cùng codebase/service image nhưng chạy consumer pool riêng để không nhân thêm bounded service. Vì không còn buffer bytes PDF trong service, giảm áp lực heap/CPU của Submission Service khi nhiều upload đồng thời — đây là động lực chính của thiết kế này. Đáp ứng FR-006..FR-011, FR-022, FR-025.

## Exam & Grading Service
Trách nhiệm: exam, paper template reference, question/criteria, rubric DRAFT/ACTIVE, DOCX table extraction, regex suggestion, assignment, grading attempt, question score và confirm. Input: REST/DOCX; output: exam/rubric/grading context, confirmed grading snapshots. Phụ thuộc Exam/Grading PostgreSQL, Submission internal REST để kiểm tra status/file access; Result gọi API snapshot. Dự kiến Java 21 + Spring Boot + PostgreSQL + Apache POI. Parser giữ grid/merge 1-1; regex chỉ prefill và activation luôn yêu cầu EXAM_OFFICE confirm (FR-001..FR-004, FR-012..FR-015, FR-024).

## Result/Review Service
Trách nhiệm: pairwise cross-grading, review lifecycle, Council decision, final result, finalize orchestration, export Excel/CSV và retention scheduler/orchestrator. Input: grading snapshots, review command, finalize/export command; output: review/final result/export stream và purge commands. Phụ thuộc Result PostgreSQL, Exam & Grading REST, Submission REST, Identity REST. Dự kiến Java 21 + Spring Boot + PostgreSQL + Apache POI/CSV library và Spring Scheduler. Quy tắc tính điểm dùng BigDecimal, RoundingMode.HALF_UP scale 2 (FR-016..FR-021, FR-024/025).

## RabbitMQ
Trách nhiệm: buffer/deliver anonymization jobs, retry queues với backoff và dead-letter sau retry kỹ thuật. Input: durable messages có jobId, submissionId, attempt; output: delivery tới Submission worker. Chỉ dùng cho công việc che phách, không dùng như event bus toàn hệ thống để tránh over-engineering. Durable queue/message + manual ack hỗ trợ FR-010 và NFR-availability.

## PostgreSQL
Bốn logical database/instance ownership: identity_db, submission_db, exam_grading_db, result_review_db. Chỉ owning service có credential vào DB; FK không vượt DB, cross-service references dùng UUID và kiểm tra qua API. Transactions chỉ cục bộ. PostgreSQL 16 dự kiến vì constraint relational database-per-service và cần unique/check/index đáng tin cậy.

## Object Storage
MinIO cho Docker Compose, API S3-compatible để có thể chuyển AWS S3. Dùng bucket/prefix tách `original` và `anonymized`; object private, không có domain/port public riêng — chỉ được chạm tới qua route pass-through `/storage/*` trên Gateway (ADR-013). Upload ORIGINAL dùng presigned POST + policy (không phải PUT thô) để MinIO tự thực thi điều kiện `content-length-range`/`key` trước khi nhận bytes, giảm khả năng client gửi sai kích thước/đúng key thao túng. ORIGINAL chỉ EXAM_OFFICE/service credential có thể lấy; ANONYMIZED chỉ cấp URL ngắn hạn sau resource authorization. Lifecycle không được tự xóa trước retention orchestration; Result/Review kích purge đúng finalized_at+1 năm (FR-008, FR-013, FR-025).

## Giao tiếp và ownership
REST synchronous dùng cho query/command cần phản hồi tức thời; RabbitMQ chỉ cho anonymization. Route `/storage/*` trên Gateway không tính là "internal REST request" giữa các service — nó là proxy tầng network thuần túy, không mang `X-User-Id`/`X-Role`/HMAC (vì presigned policy tự thân đã là cơ chế xác thực/ủy quyền cho riêng thao tác object đó). Mỗi internal request khác có requestId, user context ký và service authentication; service đích kiểm resource. Không service nào truy vấn DB của service khác. Correlation bằng UUID (`examId`, `submissionId`) nhưng PII candidateId chỉ xuất hiện ở Identity và ở snapshot kết quả lâu dài có kiểm soát trong Result sau ghép phách. Điều này giảm khả năng deanonymization trong grading path (NFR-security, BR-006/007).
